# Вложения и ширина инструментов

## Использование

Скрепка в чате и кнопка во вкладке «Файлы» открывают один выбор файлов. Можно выбрать несколько или перетащить файлы в чат/панель. Каждый файл загружается отдельно с прогрессом, отменой и повтором; после сохранения появляется сообщение и запись в общей библиотеке.

Изображения PNG/JPEG/GIF/WebP показываются в чате и библиотеке, по клику открываются крупнее. MP4/WebM воспроизводятся встроенным HTML-video, без автозапуска. Совместимость конкретного кодека зависит от браузера; при ошибке доступно скачивание. Остальные типы скачиваются. Есть ссылки скачивания в обоих местах. Текст черновика чата загрузкой не очищается. Вызов Нейрона пока не анализирует содержимое вложений.

На десктопе границу справа можно тянуть влево. Панель занимает от 320 px до 72% окна, оставляя чату минимум 360 px. Ширина сохраняется в localStorage. Стрелки меняют ширину на 32 px, Home/End задают границы, двойной клик сбрасывает к 440 px. На мобильном разделитель скрыт и инструмент занимает весь экран.

## Установка и хранение

После установки зависимостей выполнить `npm run db:generate --prefix server`, `npm run db:migrate --prefix server` и перезапустить сервер. На Windows перед генерацией Prisma может понадобиться остановить NestJS: его процесс удерживает DLL движка. Миграция `202611130003_attachments` добавляет таблицу, существующие сообщения не удаляет.

`UPLOAD_DIR` по умолчанию — `uploads` относительно рабочей папки сервера. В Docker это `/app/uploads` с постоянным volume `uploaded_files`; каталог принадлежит пользователю node. Метаданные в PostgreSQL, двоичные файлы отдельно. Резервное копирование должно включать оба хранилища. Каталог не публикуется статически и не коммитится.

Лимиты: 50 МиБ на файл, до 10 файлов в клиентской очереди, 200 файлов / 500 МиБ на комнату. Незавершённая передача отменяется при уходе из комнаты; буфер выбранного файла не переживает перезагрузку. Отмена не отзывает файл, если сервер уже успел его сохранить.

## Доставка и доступ

Guard проверяет доступ к комнате **до** multipart-interceptor и записи файла. Multer пишет поток на диск с ограничением размера, а не сохраняет 50 МиБ в памяти приложения. При успешном сохранении транзакция связывает Attachment и Message; только после commit рассылаются `message:created` и `files:changed` через существующий сокет. Ответ HTTP также объединяется по ID, чтобы повторная доставка не дублировала сообщение. Повтор загрузки использует тот же clientRequestId; лишняя временная копия удаляется.

Файлы доступны только через `/api/rooms/:roomId/files/:id/content` после проверки членства. Ссылки не содержат пути хранения. MIME для inline определяется сигнатурой, а не заявленным клиентом Content-Type. HTML/SVG и другие документы отдаются как скачивание с `nosniff`; имена очищаются от управляющих символов и путей. Видео поддерживает Range/206 для перемотки. Приватные ответы не кешируются.

Очистка чата отсоединяет сообщения, но сохраняет библиотеку комнаты. Повтор загрузки старого ID не возвращает удалённое сообщение в историю. Полное удаление комнаты, если появится такой API, должно также удалять её бинарные объекты; каскад БД сам по себе файлы на диске не удаляет. После аварийного завершения между записью файла и commit возможны сиротские объекты — для production нужен периодический сборщик с безопасным периодом ожидания.

## Масштабирование

Текущий backend — локальный диск/один сервер с постоянным volume. Для нескольких API-узлов потребуется общее хранилище или S3-совместимый backend; одного общего PostgreSQL недостаточно. Модуль `file-storage.ts` отделён от метаданных и интерфейса. На следующем этапе — S3 multipart/presigned upload, авторизованные download URL, генерация миниатюр, проверки содержимого и политика хранения. Для Socket.IO-кластера нужен Redis adapter.

В production Caddy отправляет `/api/*` прямо в NestJS. Для локального Next.js rewrite установлен `experimental.proxyClientMaxBodySize: 55mb`; такие dev-запросы могут буферизоваться Next.js, поэтому это не схема для большого потока production-загрузок.

## Проверки

`npm test --prefix server`: определение inline-типа, безопасные имена/пути, словари и существующие unit-проверки.

`npm run test:files --prefix tools`: нужны локальные frontend/backend/PostgreSQL и Edge. Создаётся отдельная комната двух участников: изображение, документ, реальный синтетический WebM, воспроизведение и Range, скачивание из чата и библиотеки, drag-and-drop, сетевой сбой и повтор, одинаковый ID без дублей, подмена MIME, отказ постороннему, файлы больше 10 МиБ через dev-proxy, отклонение больше 50 МиБ, перезагрузка и resize мышью/клавиатурой с сохранением ширины. Тест удаляет только собственные сообщения, комнаты и файлы.
