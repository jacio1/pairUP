# Публикация PairUp: VPS и домен

Выбранное имя: **pairupstudy-demo.app**. Проверка Google Registry RDAP 11 ноября 2026 года вернула `404 Not Found` — регистрации в реестре не найдено. Окончательную доступность, обычную/премиальную цену и стоимость продления проверяет регистратор при заказе. Домен пока не приобретён.

## Что заказать

- **Selectel VDS 4-8-80**: 4 vCPU, 8 ГБ RAM, 80 ГБ NVMe. В [публичной таблице тарифов](https://selectel.ru/services/cloud/vps-vds/) на дату проверки — **1100 ₽/месяц**. Выбирай продукт **VDS**, регион Москва или Санкт-Петербург, Ubuntu 24.04 LTS x86_64. Перед подтверждением проверь итоговую сумму и публичный IPv4 в панели. Для демо это оставляет запас в бюджете 1000–2000 ₽/месяц.
- Домен `pairupstudy-demo.app` через [Timeweb](https://timeweb.com/ru/services/domains/app/) или другого регистратора с поддержкой `.app`. Цена `.app` не подтверждена: сравни регистрацию и ежегодное продление до оплаты. Покупать платный SSL не нужно — Caddy выпускает сертификат автоматически.
- Если `.app` окажется дорогим, варианты `learnpairup.ru` и `pairup-study.ru` остаются запасными, но их доступность пока не подтверждена. [Timeweb](https://timeweb.com/ru/services/domains/ru/) публикует 200 ₽ за первый год `.ru`, 399 ₽ за продление на дату проверки.

Аккаунты VPS и регистратора оформляются на тебя. Email, проверку личности и оплату нужно пройти в личной панели провайдера. Пароли, API-токены и приватные SSH-ключи не отправляй в чат. Для дальнейшей настройки достаточно работающего локального SSH-профиля.

## Подключение по SSH

При создании VPS добавь свой публичный SSH-ключ. Если отдельного ключа нет, создай его в PowerShell (команда предложит задать пароль ключа):

```powershell
ssh-keygen -t ed25519 -f "$env:USERPROFILE/.ssh/pairup_demo" -C pairup-demo
Get-Content "$env:USERPROFILE/.ssh/pairup_demo.pub"
```

Не запускай генерацию поверх существующего ключа. В панель провайдера вставляется только содержимое `.pub`.

В локальный файл `~/.ssh/config` добавь, подставив публичный IP VPS:

```sshconfig
Host pairup-demo
  HostName YOUR_VPS_IP
  User root
  IdentityFile ~/.ssh/pairup_demo
  IdentitiesOnly yes
```

Первое подключение: `ssh pairup-demo`. Сверь отпечаток SSH с данными панели провайдера, если они доступны. Начальный bootstrap использует root для установки Docker; приложения внутри контейнеров запускаются непривилегированным пользователем.

## DNS и HTTPS

В DNS-панели домена создай:

| Тип | Имя | Значение           |
| --- | --- | ------------------ |
| A   | @   | публичный IPv4 VPS |

Для этой версии `www` не нужен. Не добавляй AAAA-запись без работающего IPv6. Разреши входящие TCP 22, 80, 443 в панели провайдера/межсетевом экране. PostgreSQL и порт 4000 наружу не открывай.

Проверка из PowerShell:

```powershell
Resolve-DnsName pairupstudy-demo.app -Type A
```

## Подготовка и загрузка

В корне проекта уже можно создать отдельные production-секреты:

```powershell
node deploy/configure.mjs pairupstudy-demo.app
```

Скрипт создаёт корневой `.env` и отказывается перезаписывать существующий. Этот файл игнорируется Git. Добавь туда ключ облачного резерва и URI модели, если используешь его.

Когда домен направлен на VPS и SSH работает:

```powershell
./deploy/publish.ps1 -SshHost pairup-demo
```

Скрипт упаковывает исходники и production `.env`, загружает архив по SSH, устанавливает Docker из официального Ubuntu-репозитория при необходимости и запускает Compose. Архив в `artifacts` содержит секреты — не публикуй его. Публикация не удаляет существующие тома PostgreSQL.

Проверки:

```powershell
Invoke-RestMethod https://pairupstudy-demo.app/api/health
```

Затем открой сайт с телефона и ноутбука: TEST, Presenter, сообщения в обе стороны, переключение RU/EN.

## Подключение домашнего AI

В `worker/.env` задай:

```dotenv
SERVER_URL=https://pairupstudy-demo.app
WORKER_SECRET=<значение из корневого production .env>
OLLAMA_URL=http://127.0.0.1:11434
OLLAMA_MODEL=qwen3:8b
```

Один worker работает с одним сервером. Для публичного показа останови локальный worker, поменяй адрес/секрет и запусти его заново. Пароль ведущего бери из того же корневого `.env`, а не из локального `server/.env`.

Для QR-кода и записи репетиции смотри корневой README. QR-код выбранного адреса пригоден для аудитории только после регистрации домена и запуска сайта.
