# Общие заметки и задачи

## Запуск

После установки зависимостей выполнить `npm run db:generate --prefix server` и `npm run db:migrate --prefix server`, затем перезапустить NestJS и Next.js. Docker-образ сервера применяет миграции при запуске. Миграция `202611130001_study_tools` добавляет две таблицы, существующие данные не удаляет.

В учебной комнате вкладки «Заметки» и «Задачи» теперь рабочие. Все участники с доступом к комнате могут ими пользоваться; права Presenter для этих инструментов не нужны.

## Заметки

Несколько именованных текстовых документов, совместное редактирование заголовка и текста через Yjs, автосохранение спустя 600 мс без ввода, экспорт TXT, удаление с подтверждением. Это текстовый редактор без rich-text форматирования и курсоров других участников.

Клиент отправляет CRDT-состояние, сервер объединяет его с последним состоянием в PostgreSQL. Запись выполняется через compare-and-swap по версии с повторным слиянием при конкурентной записи. Повторные и переставленные обновления безопасны. Сервер проверяет полученное состояние и длину текста. Сериализация не исполняет пользовательский HTML.

До подтверждения сервера черновик сохраняется в localStorage с ключом сессии, комнаты и документа. Он восстанавливается при возврате во вкладку или перезагрузке. Ошибки показываются в редакторе; есть повторная отправка и повтор при событии online. При несохранённых изменениях браузер получает beforeunload-предупреждение. Это восстановление локальных правок, а не полноценная работа всего приложения офлайн. После подтверждения черновик удаляется; запоздалый ответ закрытого редактора не удаляет более новый черновик.

## Задачи

Создание, изменение текста, переключение выполнения, общий прогресс, удаление с подтверждением. Создания имеют клиентский UUID для безопасного повтора. Изменение/удаление проверяет версию: устаревшее действие возвращает `TOOL_CONFLICT`, а не перезаписывает актуальные данные. В редакторе можно явно отбросить устаревший черновик и загрузить текущую задачу.

## Доставка и ограничения

Все HTTP-запросы проверяют доступ через `Auth.roomAccess`. После успешной записи сервер посылает `tools:changed` только в нужную Socket.IO-комнату. Существующий единственный клиентский сокет инвалидирует RTK Query-кеш; при переподключении история инструментов запрашивается заново. Открытые инструменты дополнительно обновляются раз в 15 секунд, чтобы восстановиться после пропущенного события.

Лимиты: 30 заметок и 100 задач в комнате; заголовок заметки 120, текст 20 000, задача 300 символов. CRDT-состояние до 256 КиБ. Длинная история правок также может достигнуть этого лимита: тогда нужно создать новую заметку и перенести актуальный текст. Данные инструментов независимы от очистки истории чата.

Лимит количества элементов защищён блокировкой строки комнаты в PostgreSQL. Нет обязательного состояния заметок в памяти одного NestJS-процесса: несколько API-узлов могут выполнять конкурентные изменения. Для нескольких Socket.IO-узлов всё ещё нужны общий Redis adapter, распределённый rate limit и настройка балансировщика; для большого потока правок — отдельный сервис документов, дельты Yjs и компактизация. Текущая реализация передаёт ограниченное полное состояние документа и ориентирована на учебные комнаты, а не на тысячи соавторов одного документа.

## Проверки

`npm test --prefix server`: слияние конкурентных CRDT-правок, перестановка и повторы обновлений, ограничения/валидация, доступ перед чтением и записью, паритет словарей RU/EN.

`npm run test:study-tools --prefix tools`: нужны локальные frontend, backend и PostgreSQL. Два браузера с разными языками проверяют заметки/задачи, реальную доставку, конкурентные записи, конфликт версий, восстановление черновика при сбое сохранения, экспорт, повтор создания, удаление и мобильный экран. Тест создаёт собственные объявления, комнаты и сессии, удаляет только их; общий чат не очищается.

[Модель обновлений Yjs](https://docs.yjs.dev/api/document-updates).
