# Запуск PairUp на домашнем ПК

## Постоянный домен pair-up.ru

Для именованного Cloudflare Tunnel сохранить выданный токен в локальном `.env.home` как `CLOUDFLARE_TUNNEL_TOKEN`, а `PUBLIC_ORIGIN` установить в `https://pair-up.ru`. Токен нельзя помещать в Compose-файлы или Git.

`start.ps1` при наличии токена автоматически подключает `compose.home.permanent.yaml`. Туннель получает токен через переменную окружения, а не аргумент командной строки, и запускается с `restart: unless-stopped`. В этой конфигурации скрипт не ищет временный адрес и не меняет домен при перезапуске.

В панели Cloudflare у туннеля добавить маршрут Published application: домен `pair-up.ru`, поддомен пустой, сервис `HTTP`, адрес `proxy:80`. Именно `proxy`, а не `localhost`: cloudflared работает в Docker-сети рядом с Caddy. DNS-запись маршрута создаётся в Cloudflare. Пока делегирование домена не обновилось и маршрут не добавлен, соединение туннеля может быть Healthy, но сайт по домену ещё недоступен.

Постоянный адрес не отменяет зависимость от включённого ПК, Docker и домашнего интернета.

Публичный HTTP для `pair-up.ru` перенаправляется на HTTPS кодом 308 с сохранением пути и параметров. Проверяется `X-Forwarded-Proto`, который Cloudflare выставляет по протоколу посетителя: внутренний переход Tunnel → Caddy остаётся HTTP и не вызывает цикл редиректов. Для HTTPS добавляется HSTS на сутки. Локальный доступ worker к `127.0.0.1:18080` не перенаправляется. Авторизация по-прежнему допускает только настроенный HTTPS-origin и использует Secure cookie.

## Временный пробный адрес

Для пробного публичного запуска используется отдельный Docker Compose-проект `pairup-home`: PostgreSQL, production-сборки NestJS/Next.js, Caddy и исходящий Cloudflare Quick Tunnel. Проброс портов роутера и собственный домен не требуются. Открывается только приложение через HTTPS; PostgreSQL и Ollama наружу не публикуются.

## Первый запуск

Запустить Docker Desktop, затем из корня проекта:

```powershell
powershell -ExecutionPolicy Bypass -File deploy/home/start.ps1 -Build
```

Скрипт создаёт `.env.home` с отдельными случайными секретами, собирает приложение, запускает туннель и подставляет его HTTPS-адрес в разрешённые источники HTTP/WebSocket сервера. Адрес выводится в терминал. Исходные локальные база и настройки разработки не используются; для публичной копии выделены отдельные Docker volumes. При первом запуске создаются стандартные объявления проекта.

Файлы `.env.home` и `worker/.env.home` исключены из Git. Пароль ведущего находится в поле `PRESENTER_PASSWORD` корневого `.env.home`. Публичный вход TEST остаётся доступен посетителям.

## Повторный запуск

```powershell
powershell -ExecutionPolicy Bypass -File deploy/home/start.ps1
```

Если изменялся код, добавить `-Build`. При сохранённом работающем туннеле сохраняется его адрес; после остановки/пересоздания туннеля Quick Tunnel выдаёт новый адрес. Скрипт повторно синхронизирует `PUBLIC_ORIGIN`. Данные и секреты при перезапуске не сбрасываются.

## Локальный Нейрон

Нужны установленный Ollama, загруженная `qwen3:8b` и зависимости worker (`npm ci --prefix worker`). Ollama должен слушать только loopback, как в стандартной локальной конфигурации.

```powershell
powershell -ExecutionPolicy Bypass -File deploy/home/start-ai.ps1
```

Worker работает на Windows, поэтому использует локальный Ollama и GPU. Он подключается к backend через `http://127.0.0.1:18080` с отдельным секретом домашнего развёртывания. Состояние прогрева — `artifacts/home/worker.log`, ошибки — `artifacts/home/worker-error.log`. После прогрева войти ведущим по публичному HTTPS-адресу и нажать «Позвать Нейрона».

## Остановка

```powershell
powershell -ExecutionPolicy Bypass -File deploy/home/stop.ps1
```

Останавливает контейнеры этого развёртывания и запущенный данным скриптом AI-worker. Том базы и загруженные файлы сохраняются. Не применять `docker compose down -v`, если данные нужны.

## Ограничения

- ПК и Docker Desktop должны оставаться включёнными, без перехода в сон. Автозапуск Windows и изменение параметров питания не настраиваются этими скриптами.
- Quick Tunnel — временный тестовый адрес без гарантии доступности. Для постоянного URL нужен именованный туннель со своим доменом или другой постоянный способ публикации. [Документация Cloudflare](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/).
- Обычный HTTP-туннель не публикует медиапорты LiveKit. Голос в этой конфигурации не включён. Для него отдельно нужны доступный LiveKit/SFU и сетевые настройки UDP/TURN.
- Облачный AI-резерв в домашней конфигурации не настроен. Без локального worker чат продолжает работать, запрос Нейрону завершится сообщением о недоступности AI.
- Это отдельная база для публичного показа; её резервное копирование и длительное хранение нужно организовать отдельно.
